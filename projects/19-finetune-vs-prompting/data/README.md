# `19-finetune-vs-prompting/data/`: fine-tuning dataset

Generated by `python projects/19-finetune-vs-prompting/run.py dataset` (also run by the
end-to-end demo) from the deterministic synthetic corpus in
[`finetune_lab/corpus.py`](../finetune_lab/corpus.py). Every line is one chat example in the
format Azure OpenAI fine-tuning accepts: a system message (the short fine-tuning prompt), a
user message (the PII-scrubbed page text) and an assistant message (the label). All names,
numbers and addresses in the source corpus are fictional and are replaced with placeholders
such as `[SSN]` before anything is written.

| File | What it does |
|---|---|
| [`train.jsonl`](train.jsonl) | Training split (70% of loan files). |
| [`val.jsonl`](val.jsonl) | Validation split (15%); the promotion gate decides on this split. |
| [`test.jsonl`](test.jsonl) | Test split (15%); reported, never used to decide. |
| [`manifest.json`](manifest.json) | Build report: raw count, PII redactions by type, duplicates and label conflicts removed, leakage drops, split and label counts, and the sha256 of each file. |

## Checks applied before writing

1. PII scrub (emails, SSNs, account numbers, phones, addresses, names).
2. Dedup on a normalised fingerprint; copies with conflicting labels are all dropped.
3. Split grouped by loan file, so one borrower's pages never span splits.
4. Leakage check across splits (same loan, same fingerprint, or 3-shingle Jaccard ≥ 0.8);
   offenders are dropped from val/test, and the build fails if any remain.

`test_committed_data_is_reproducible_from_the_seed` rebuilds the data and compares hashes.
