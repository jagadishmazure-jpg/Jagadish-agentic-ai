# `finetune_lab/`: fine-tuning vs prompting, measured and gated

The importable package for project 19. It builds a PII-scrubbed, deduplicated, leakage-checked
dataset of mortgage document pages in chat fine-tuning format, trains a small offline
classifier head on it, runs the prompted base model and the fine-tuned head through the shared
eval harness, and promotes the fine-tuned model only if it beats the champion. A LangGraph
graph serves the registry champion with a fallback to the prompted baseline, and an optional
script runs the same data through Azure OpenAI fine-tuning (dry run by default).

| File | What it does |
|---|---|
| [`__init__.py`](__init__.py) | Package docstring only. |
| [`azure_finetune.py`](azure_finetune.py) | Optional Azure OpenAI fine-tuning: `plan()` validates the files and prints the requests; `--execute` (needs `AZURE_OPENAI_ENDPOINT` and `AZURE_OPENAI_API_KEY`, refuses under `CI` or pytest) uploads UTF-8-BOM copies with `purpose="fine-tune"`, creates a supervised job, polls status and events, and with `--deploy` creates a deployment through ARM. `SFT_MODELS` lists the models documented for supervised fine-tuning. |
| [`baseline.py`](baseline.py) | The prompted base model: `PromptedClassifier` (rubric + three examples in the system prompt, fallback chain, parses the label) and `mock_responder`, the deterministic offline model that scores the rubric's cue phrases. `Prediction` is shared by both variants. |
| [`compare.py`](compare.py) | Comparison harness: `classification_metrics` (accuracy, macro-F1, per-class F1, confusion), `evaluate` (runs a classifier through `shared.evals.harness.run_suite` and adds latency and token counts), `run_comparison` (register, measure, gate, promote), `load_registry`, `render_table` and `main` (`--write` refreshes `registry/`, `evals/comparison.json` and the project README table). |
| [`corpus.py`](corpus.py) | Deterministic synthetic loan-file pages (seed 19): ten document types with alternative headings, borrowed phrases, OCR noise, rescanned duplicates, 3% label noise and fictional PII, which is returned with each `Record` so tests can prove it was removed. |
| [`dataset.py`](dataset.py) | `build()`: scrub → fingerprint dedup (label conflicts drop every copy) → split by loan file 70/15/15 → leakage check (loan, fingerprint, 3-shingle Jaccard ≥ 0.8) → chat JSONL and `manifest.json` with hashes. Also `find_leaks`, `validate_chat_file`, `load_split` and `LeakageError`. |
| [`demo.py`](demo.py) | CLI behind `run.py`: end-to-end demo (dataset, comparison, serving, rollback) and the `dataset`, `compare` and `azure` subcommands; `--mermaid PATH`. |
| [`eval_suite.py`](eval_suite.py) | `run_case` for the golden set (route and type; a violation is planted PII reaching the LOS or an injected page being filed), `chaos_scenario` and `CHAOS_CHECKS`. |
| [`graph.py`](graph.py) | `build_graph()`. Nodes: `intake` (scrub, injection check), `classify` (champion, fallback to the prompted baseline, confidence floor 0.55), `file_document` (LOS via MCP, outbox when the LOS is down) and `human_review`. |
| [`labels.py`](labels.py) | The ten labels, their definitions and cue phrases, the baseline system prompt (rubric + examples) and the short system prompt used for fine-tuning. |
| [`pii.py`](pii.py) | `scrub()` and `contains_pii()`: emails, SSNs, account numbers, phones, street addresses and names after OCR-tolerant labels, replaced with typed placeholders. |
| [`registry.py`](registry.py) | `ModelRegistry`: register prompt and fine-tuned versions (dataset hash, system prompt, artifact sha256), record metrics, `gate`, `promote` (raises `PromotionRefusedError`), `rollback`, an event log, and `classifier()`, which verifies the artifact hash before serving. |
| [`sor.py`](sor.py) | Loan origination system MCP server (`los.file_document`, `los.queue_review`) and the `mi-doc-classifier` gateway. |
| [`trainer.py`](trainer.py) | The offline fine-tuning path: word, bigram and character-trigram features, TF-IDF, scikit-learn logistic regression, exported to `LinearTextModel` (JSON, NumPy inference, no pickle). `train()` and `FineTunedClassifier`. |

## Graph

```
intake (scrub PII, injection check) -> injection -> human_review
                                   -> classify (champion; fallback: prompted baseline)
classify -> confidence >= 0.55 -> file_document (LOS via MCP; outbox if down)
         -> low confidence / every model down -> human_review
```

## Design notes

- The comparison is regenerated by a test, so the committed numbers always match the code.
- The fine-tuned model is called with the same one-line system prompt it was trained with; the
  registry stores the prompt with the version.
- `azure_finetune.py` never runs in tests or CI; its tests only exercise the plan and the
  guards.

## Run

```bash
python projects/19-finetune-vs-prompting/run.py                    # demo (offline, mock LLM)
python projects/19-finetune-vs-prompting/run.py compare --write    # refresh registry/ + results table
python projects/19-finetune-vs-prompting/run.py --mermaid projects/19-finetune-vs-prompting/graph.mmd  # also refresh the Mermaid diagram
pytest projects/19-finetune-vs-prompting                           # tests
python -m evals --project 19                # golden-set eval
CHAOS_FAULTS=model:finetuned python projects/19-finetune-vs-prompting/run.py   # demo with the fine-tuned deployment down
```
